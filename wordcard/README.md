# 单词卡制作（正式版）

把单词表排成 A4 纸、双面打印、裁开就是一张张单词卡。
纯 **HTML + 浏览器原生 ESM**，没有构建步骤、没有前端依赖，文字始终是矢量文本。

```
① 数据导入  import.html    选词表 / 导入 JSON、Markdown 表格、CSV → 直接编辑 → 下一步
② 制作卡片  make.html      4 个预设 + 常规设置 + 细节设置 → 打印 / 另存为 PDF
```

旧的实验版完整保留在 [`demo/`](demo/)，行为和样式都还在。

## 快速开始

需要 Node.js 22+（只用来起一个静态服务器；页面本身不需要 Node）：

```bash
node server.mjs          # 或 npm start
# 打开 http://localhost:8080/
```

> 浏览器不允许从 `file://` 加载 ES module，词表也要用 `fetch` 读取，所以不能直接双击 HTML。
> 部署到 Nginx / GitHub Pages / 对象存储时，把整个目录作为静态站点发布即可，不需要 `server.mjs`。

服务器参数：

```bash
node server.mjs --port 9000          # 换端口
node server.mjs --host 127.0.0.1     # 只允许本机访问（默认 0.0.0.0，局域网可访问）
```

## 数据

### 内置词表

`data/catalog.json` 是词表目录，当前内置一套 **精筛2900**：

```json
{
  "datasets": [
    { "id": "jing-sai-2900", "name": "精筛2900", "file": "jing-sai-2900.json" }
  ]
}
```

`data/jing-sai-2900.json` 是内置的 **精筛2900** 词表，共 2946 条，序号严格沿用源表编号 1–2946。
它由 `scripts/build-jing-sai.mjs` 从 `tmp/答案对照表.txt` 转换生成；源表里的字母分隔卡、残缺项和格式错误都按原样保留，不重排、不补号。

### 格式

与 zzti-web 的卡片数据一致，额外增加可选的 `i` 字段：

```json
[
  { "front": "abandon", "back": "v. 放弃；抛弃", "content": "/əˈbændən/", "i": 1 },
  { "front": "benefit", "back": "n. 好处；v. 使受益", "content": "/ˈbenɪfɪt/", "i": 2 }
]
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `front` | 是 | 正面（单词） |
| `back` | 否 | 反面（释义） |
| `content` | 否 | 附加信息：音标、词性、例句等 |
| `i` | 否 | 序号。有它时卡片上印的序号就是它；没有时按顺序从 1 编号 |

也兼容 zzti-web 题库里的 `q` / `ans` / `con` 命名。换行直接写 `\n`。

在 `data/catalog.json` 里增加一项，就会出现在导入页的下拉菜单里。详见 [`data/README.md`](data/README.md)。

### 序号范围

选中预设词表后，可以填「起始序号 — 结束序号」，只把范围内的词带到制作页。
筛选依据是 `i`；没有 `i` 时按数组顺序。范围、来源、当前编辑内容都会自动保存在本机浏览器里。

### 导入自己的数据

支持三种格式，导入向导会自动识别，也可以手动指定：

- **JSON**：数组、`{ data: [...] }`、`{ cards: [...] }`、多层分组的题库结构都可以摊平成表格。
- **Markdown 表格**：自动忽略表格上下的说明文字；识别到多张表时可以选择用哪一张；没有分隔行、`\|` 转义、全角竖线、`**粗体**`、`<br>`、行内代码都能处理。
- **CSV / TSV**：自动识别 `,` `;` Tab，支持引号、字段内换行和 `""` 转义。请尽量保存为 UTF-8 编码。

识别后进入「确认表格与字段」：

- 首行是不是表头，可以切换；
- 正面 / 反面 / 附加信息 / 序号各自对应哪一列，可以手动映射；标题里带「序号、单词、释义、音标、备注」等字样的会自动猜；
- 右侧实时预览前 5 张；
- 替换当前数据，或追加到自定义数据末尾。

预设词表按序号范围读取时不支持「追加」和「添加一行」（否则会破坏连续范围）；需要增删就导入为自定义数据。

## 制作卡片

### 四个预设

| 预设 | 纸张 | 长边 | 短边 | 卡片尺寸 |
|---|---|---|---|---|
| 竖版 · 长条 | A4 竖向 | 16 | 3 | 70.0 × 18.6 mm |
| 竖版 · 宽条 | A4 竖向 | 16 | 2 | 105.0 × 18.6 mm |
| 竖版 · 标准 | A4 竖向 | 8 | 4 | 52.5 × 37.1 mm |
| 横版 · 大卡 | A4 横向 | 4 | 4 | 74.3 × 52.5 mm |

四个预设的安全区都是 **上 0 / 右 0 / 下 0 / 左 15mm**，方便左侧装订或夹夹子。
应用预设时，纸张留白和卡片间距也会归零，和实测样式保持一致；字体、颜色等文字设置会保留。

- 「长边张数」永远指沿纸张长边（297mm）方向的张数；「短边张数」沿短边（210mm）方向。切换横竖版时含义不会变。
- 左侧设置区默认 420px，可以拖动中间的分隔线调整；双击分隔线恢复 420px。
- 常规设置下面是折叠的细节分组：纸张留白、卡片间距、边框、字体、字重、行高、颜色、对齐、附加信息、自动缩字号、双面镜像等，默认全部收起。

### 背面镜像

背面相对正面可以选「左右镜像 / 上下镜像 / 旋转 180° / 不镜像」。
镜像的是**摆放几何**（卡片落在哪一格、安全区在哪条边、序号在哪个角），文字本身永远不翻转。

不确定打印机怎么翻纸时，在「双面打印」细节里点 **打印一张对位测试**：会临时变成 2×2 的 1/2/3/4 数字卡，双面打印后对着光看数字是否重合；退出测试会恢复原来的设置和数据。

### 手机 / 平板

窄屏（≤900px）时：

- 右侧预览收起为设置区底部常驻的 **「预览卡片」** 按钮，点击弹出全屏预览；
- 预览弹窗内可以缩放、适应宽度、打印；
- 设置区和打印按钮都保持可用。

导入页同样：窄屏下由底部的 **「预览数据」** 按钮打开表格预览，仍然可以直接编辑。

## 打印

1. 浏览器打印 → 边距选 **无**，缩放 **100%**，取消页眉页脚；
2. 双面打印选 **长边翻转**；对不齐先做对位测试；
3. 打印目标选 **另存为 PDF**，得到的就是矢量 PDF；
4. 用了卡片底色或边框颜色时，勾选 **背景图形**。

纸张留白和卡片间距默认都是 0：卡片直接铺到纸边，相邻卡片共用裁切线，裁的时候最省事。
屏幕上的蓝色安全区参考线和每页左上角的「正面 / 反面」角标不会打印；页码会打印。

## 测试

```bash
npm test
# 或
bash tests/run.sh
```

会临时启动服务器，依次跑：

- 单元测试：预设几何、镜像、分页、序号、Markdown / CSV / JSON 解析、列映射；
- 端到端：预设词表加载、序号范围、单元格编辑、跳转制作页、i 序号、预设切换、细节折叠、拖拽中线、对位测试、手机预览、JSON 导入、添加 / 删除行；
- 打印：横竖版页数、A4 方向、无空白页、卡片尺寸、自动缩字号无溢出、PDF 文字可提取。

依赖：`google-chrome`（或 `CHROME=` 指定）、`pdfinfo` / `pdftotext`（poppler）。Node 22+（测试脚本用了 Node 自带 WebSocket）。

页面本身建议使用较新的 Chrome / Edge（也支持新版 Safari / Firefox）；核心排版使用 CSS `zoom` 和原生 `<dialog>`。

## 旧版

`demo/` 是改造前的实验版，仍可直接双击 `demo/index.html` 使用（旧版用的是普通 `<script>`，不依赖服务器）。
新版沿用它的排版算法、CSS 变量体系、背面镜像、自动缩字号和打印方案。

## 已知取舍

- 页面高度取「纸张高度 − 0.1mm」，避免 Chrome 因为四舍五入多吐一张空白页；PDF 页面尺寸会比 A4 少 0.1mm，打印时无影响。
- 自动缩字号是逐格二分搜索；2900 张卡片首次渲染需要一点时间，但只看得到当前页，分页和滚动正常。
- 数据保存在浏览器 `localStorage` 里，换浏览器/设备不会自动同步；分发时把 JSON 放进 `data/` 才是长期的数据源。
- 预设词表按范围加载时不能「追加」或「添加一行」（可以删除和编辑）；需要改词表就修改 JSON 或导入为自定义数据。
